Machines modestes

matOS vise les PC anciens : 64 bits uniquement, 4 Go de RAM.

Les processeurs 32 bits ne sont pas pris en charge

Debian 13 n'a plus de noyau 32 bits. Les Atom les plus anciens (N270, N450…) sont en 32 bits : matOS ne démarrera pas dessus.

Ce qui est prévu

  • Mémoire : swap compressé en mémoire (zram), earlyoom (termine le programme le plus gourmand avant que le système ne se bloque, le bureau étant protégé), journaux limités.
  • Disque : l'image est compressée par petits blocs pour que les logiciels se lancent vite depuis une clé ou un disque dur ; l'ordonnanceur BFQ garde le bureau réactif pendant une copie ; le démarrage n'attend pas le réseau.
  • Bureau : XFCE. Au premier démarrage, les effets visuels (composition d'xfwm4) sont coupés sur une machine à 4 Go ou sans accélération 3D.
  • Processeur : paquets Debian amd64 de base (sans AVX exigé) ; l'environnement SageMath est figé au niveau x86-64 de base pour fonctionner sur de vieux processeurs.
  • UEFI 32 bits : un chargeur bootia32.efi est inclus pour les tablettes et mini-PC dont le micrologiciel UEFI est en 32 bits avec un processeur 64 bits (non testé sur du vrai matériel).

Ce qui tient à 4 Go

Mesuré dans une machine virtuelle avec 4 Go de RAM et un processeur de génération Core 2 : le bureau complet 45 secondes après le lancement, 1,9 Go de mémoire occupée avec la page de bienvenue ouverte dans Firefox, aucun service en échec. Le bureau, le navigateur, LaTeX, Python, Xcas, Maxima, GAP, PARI/GP, Singular, R, Octave et Geany sont des usages normaux pour cette taille.

Gourmands : SageMath, GeoGebra 6 et, dans les modules, Lean avec Mathlib, RStudio et VSCodium. Lancez-les un par un, fermez le reste avant, ou préférez Xcas, wxMaxima, Geany et TeXstudio, bien plus légers. Dans Lean, gardez des imports ciblés : import Mathlib charge toute la bibliothèque. La consommation mémoire réelle de SageMath et de Lean n'a pas encore été mesurée : vos retours sont les bienvenus (Compatibilité).
